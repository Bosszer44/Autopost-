## 🚀 วิธีเริ่มใช้งาน

### สิ่งที่ต้องเตรียม

1. บัญชี **GitHub**
2. **Telegram Bot Token** — สร้างผ่าน [@BotFather](https://t.me/BotFather)
3. **Target Chat ID** — ID ของกลุ่ม/แชทที่ต้องการให้โพสต์

### ขั้นตอนที่ 1: สร้าง Repository

1. กด **"Use this template"** หรือสร้าง Repository ใหม่
2. อัปโหลดไฟล์ทั้งหมดในโปรเจกต์นี้ขึ้นไป

### ขั้นตอนที่ 2: ตั้งค่า Secrets

ไปที่ Repository ของคุณ → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**

สร้าง Secrets 2 ตัวนี้:

| ชื่อ Secret | ค่า |
|-------------|------|
| `TELEGRAM_BOT_TOKEN` | Telegram Bot Token ที่ได้จาก @BotFather |
| `TELEGRAM_TARGET_CHAT_ID` | Chat ID ของกลุ่ม/แชทปลายทาง (เช่น `-1001234567890`) |

> 💡 **วิธีหา Chat ID:** เพิ่มบอทเข้ากลุ่ม ส่งข้อความ 1 ข้อความ แล้วเปิดลิงก์นี้:
> `https://api.telegram.org/bot<TOKEN ของคุณ>/getUpdates`

### ขั้นตอนที่ 3: เปิดใช้งาน Workflow

1. ไปที่แท็บ **Actions** ใน Repository
2. เลือก **"Telegram Auto Post"** ที่แถบด้านซ้าย
3. กด **"Enable workflow"**

ระบบจะรันอัตโนมัติทุกๆ **5 นาที** เพื่อ:
- ตรวจสอบคำสั่ง/ข้อความใหม่ที่ส่งมาที่บอท
- เพิ่ม URL เข้าคิว
- ตรวจสอบรายการที่ถึงกำหนดเวลา
- โพสต์ URL ที่ถึงเวลา 1 รายการ
- บันทึกสถานะกลับไปยัง GitHub

### ตอบโต้ปุ่มทันที

GitHub Actions ไม่สามารถตอบปุ่มทันทีได้ เพราะระบบเริ่มทำงานเป็นรอบทุก 5 นาที หากต้องการให้ปุ่มและคำสั่งตอบกลับทันที ให้รันบอทในเครื่องหรือบริการที่เปิดทำงานตลอดเวลา:

```bash
set TELEGRAM_RUN_MODE=worker
python bot.py
```

บน Linux/macOS ใช้ `export TELEGRAM_RUN_MODE=worker` แทนคำสั่ง `set` โหมดนี้ใช้ long polling และจะรับ callback จากปุ่มทันที โดยต้องหยุด workflow ที่รัน `getUpdates` อยู่ เพื่อไม่ให้มีตัวรับอัปเดตซ้ำกัน

### ขั้นตอนที่ 4: เริ่มใช้งานบอท

1. เปิดแชทกับบอท Telegram ของคุณ
2. ส่ง `/start` เพื่อเปิดแผงควบคุม
3. กด **➕ เพิ่มลิงก์** แล้ววาง URL (1 บรรทัดต่อ 1 ลิงก์)
4. กด **▶️ เริ่มโพสต์** เพื่อเริ่มต้นกำหนดการ

### ตรรกะการทำงานของคิว

- URL จะถูกจัดตารางตามช่วงเวลาใน `interval_minutes` (ค่าเริ่มต้น: **60 นาที**)
- แต่ละรอบการรันจะโพสต์ได้สูงสุด **1 URL** ต่อครั้ง
- ระบบตรวจทุก 5 นาที เวลาจริงอาจคลาดเคลื่อนเล็กน้อย
- ถ้า GitHub Actions ถูกระงับ ระบบจะกลับมาทำงานต่ออัตโนมัติเมื่อเปิดใช้งานใหม่

## ⚙️ การตั้งค่า

### ปรับช่วงเวลาโพสต์

แก้ไขไฟล์ `data/state.json` แล้วเปลี่ยนค่า `interval_minutes`:

```json
{
  "interval_minutes": 60,
  ...
}
```

### โครงสร้างไฟล์ State (`data/state.json`)

```json
{
  "queue": [
    {
      "url": "https://example.com/article",
      "status": "pending",
      "scheduled_at": "2026-09-02T10:00:00+07:00",
      "sent_at": null
    }
  ],
  "running": true,
  "next_run": "2026-09-02T10:00:00+07:00",
  "last_update_id": 12345,
  "interval_minutes": 60,
  "admin_user_ids": []
}
```

**ค่าสถานะ:**
- `pending` — รอส่ง
- `sent` — ส่งสำเร็จแล้ว
- `skipped` — ถูกข้าม

## ⚠️ ข้อควรทราบ

- **กำหนดการ GitHub Actions** เป็นแบบประมาณเวลา อาจคลาดเคลื่อนได้ไม่รับประกันวินาทีเป๊ะ
- **1 URL ต่อรอบ** — ส่งได้สูงสุด 1 ลิงก์ต่อการรันทุก 5 นาที
- **โควตาฟรี** — GitHub Actions ให้ 2,000 นาที/เดือน สำหรับบัญชีฟรี (บอทนี้ใช้ ~90 นาที/เดือน)
- **ห้าม commit Secrets** — ใช้ GitHub Secrets เสมอ ห้ามใส่ Token ลงในไฟล์โดยตรง
- **สิทธิ์บอท** — ในกลุ่ม ต้องให้สิทธิ์บอทสามารถอ่านข้อความและส่งข้อความได้
